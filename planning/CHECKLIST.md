# צ'ק ליסט: מה צריך כדי להתקדם ומה חסר

**עודכן 16.10.2026, אחרי ההחלטה לבנות קודם אתר ווב (החלטה 3).** בכל שורה כתוב מי מבצע: **אתה** (החלטה, פנייה, חשבון או כסף), **פיתוח** (עבודה בקוד), או **שניהם**.

## איפה אנחנו
יש אתר שעובד מקומית לגוש דן (`site/`). הוא כולל:
- חיפוש כתובות, תחנות ו"המיקום שלי", ובחירת נקודה במפה.
- מפה עם המסלול.
- מנוע מסלולים בדפדפן (חיפוש לוקח עד חצי שנייה).
- לוחות זמנים להיום ולשני הימים הבאים, וזמן אמת מ־Stride.

הוא עוד לא פורסם באינטרנט. הלמידה האישית, שמבדילה את המוצר, עוד לא התחילה.

## 1. כדי שהאתר יעלה לאוויר
- [x] **פיתוח:** מאגר git לפרויקט.
- [ ] **אתה:** ליצור ב־GitHub מאגר ציבורי ריק (שם מוצע: `transit-gushdan`). בהגדרות, תחת Pages, לבחור Source = GitHub Actions.
- [ ] **שניהם:** דחיפה ראשונה (באישורך), ובדיקה שה־workflow מצליח להוריד את הנתונים ממשרד התחבורה מהשרתים של GitHub.
- [ ] **פיתוח:** אם משרד התחבורה חוסם את GitHub, לבנות את הנתונים במחשב שלך ולדחוף אותם משם (`docs/SITE.md`).
- [ ] **אתה (אופציונלי):** שם דומיין משלך במקום הכתובת של GitHub.

## 2. החלטות שמחכות לך
- [ ] איזה מנוע: להישאר עם המנוע שלנו, או לעבור למנוע חינמי על שרת. זה תלוי בתוצאות ההשוואה, שתיכתבנה ב־`docs/ROUTING_ENGINE.md`.
- [ ] להרחיב מגוש דן לכל הארץ? באוטובוסים זה כבד לדפדפן, ולכן כנראה יצריך שרת.
- [ ] שם קבוע לאתר ולמוצר.
- [ ] תקציב, אם בעתיד יידרשו שירותים בתשלום (מפות, חיפוש כתובות, שרת).

## 3. פניות וגורמים חיצוניים
- [ ] **אתה:** לשלוח למשרד התחבורה בקשת גישה ל־SIRI-SM (ptsupport@mot.gov.il).
- [ ] **אתה:** לבדוק את תנאי השימוש של Photon, של אריחי OpenStreetMap ושל Stride לאתר ציבורי. אם יהיה עומס, לעבור לשירות בתשלום.
- [ ] **אתה:** מדיניות פרטיות ותנאי שימוש קצרים לאתר. מומלץ עם ייעוץ משפטי.
- [ ] **אתה (אופציונלי):** לספר לסדנא לידע ציבורי (Open Bus) על השימוש ב־Stride.

## 4. שיפורים לאתר
- [ ] **פיתוח:** הליכה לפי רחובות ולא בקו ישר. צריך נתוני OpenStreetMap ועיבוד מראש.
- [ ] **פיתוח:** לצייר את המסלול על המפה לפי צורת הקו (shapes.txt), ולא בקו ישר בין התחנות.
- [ ] **פיתוח:** להריץ את החיפוש ב־Web Worker, כדי שהדף לא ייתקע בטלפונים חלשים.
- [ ] **פיתוח:** מחירי נסיעה (FR-02).
- [ ] **פיתוח:** מצב לא מקוון (PWA), כדי שהאתר ייפתח מהר ויעבוד גם בלי קליטה.
- [ ] **שניהם:** בדיקה בשטח: להשוות את מה שהאתר הציג לזמן שבו האוטובוס הגיע בפועל.
- [ ] **פיתוח:** נגישות: בדיקה עם קורא מסך ובדיקת ניגודיות.

## 5. מה חסר בפרויקט
- [ ] פרסום (סעיף 1).
- [ ] נגישות בתחנות ומעליות: אין נתונים.
- [ ] התאמה אישית: אין עדיין מדידות. באתר נצטרך להחליט מה נשמר בדפדפן ומה לא.
- [ ] מסמכים מהאפיון (פרק 20): Wireframes, חוזי API לשרת עתידי, תוכנית בדיקות, מדיניות פרטיות.
- [ ] Android: נדחה לשלב מאוחר יותר (החלטה 3).

## הסדר המומלץ
1. ליצור מאגר ב־GitHub ולפרסם (סעיף 1).
2. לשלוח את הבקשה למשרד התחבורה.
3. לראות את תוצאות ההשוואה של המנועים ולהחליט.
4. שיפורי האתר: הליכה לפי רחובות, צורת הקווים, Web Worker.
5. בדיקה בשטח, ואחר כך למידה אישית.
