# צ'ק ליסט: מה צריך כדי להתקדם ומה חסר

**נכון ל־16.10.2026.** בכל שורה כתוב מי מבצע: **אתה** (החלטה, פנייה, חשבון או כסף), **פיתוח** (עבודה בקוד), או **שניהם**.

## איפה אנחנו באמת
יש אפיון מלא ואב־טיפוס ווב: הוא מחשב מסלולים על לוחות זמנים אמיתיים של תל אביב ורכבת ישראל, ומציג זמן אמת זמני. אבל עדיין אין אפליקציית Android, אין שרת, אין מנוע מסלולים קבוע, ואין תיעוד נסיעות. החלק שמבדיל את המוצר, הלמידה מנסיעות בפועל, עוד לא התחיל. אנחנו בתחילת שלב 0 (היתכנות), לא לפני MVP.

## 1. חוסם עכשיו
- [ ] **אתה:** לפתוח מאגר git לפרויקט. כרגע אין גיבוי ואין היסטוריית שינויים, ושינוי בטעות לא ניתן לשחזור. (פיתוח יכול להקים את המאגר באישורך.)
- [ ] **אתה:** לשלוח למשרד התחבורה בקשת גישה ל־SIRI-SM (ptsupport@mot.gov.il). לשאול על כתובת IP קבועה, תנאי שימוש, עלות ו־SIRI-VM. האישור לוקח זמן, ובלעדיו אין זמן אמת רשמי.
- [ ] **שניהם:** לבחור מנוע מסלולים קיים. יש כרטיס משימה מוכן להשוואה בין OpenTripPlanner ל־MOTIS.

## 2. החלטות שמחכות לך
- [ ] אזור הפיילוט הראשון ותנאי ההצלחה שלו. אב־הטיפוס עובד על תל אביב יפו.
- [ ] האם ה־MVP כולל את כל אמצעי התחבורה, או מתחיל במסלולים עם רכבת ורכבת קלה.
- [ ] חשבון משתמש כבר בגרסה הראשונה, או פרופיל מקומי במכשיר.
- [ ] אילו נתוני משתמש נשמרים בשרת ואילו רק במכשיר.
- [ ] כמה זמן שומרים מיקום גולמי.
- [ ] זיהוי מקטעים אוטומטי לגמרי, או עם אישור ותיקון של המשתמש.
- [ ] תקציב חודשי לשרתים ולשירותים, ומי מפתח: אתה לבד, צוות, או קבלן.

## 3. פניות וגורמים חיצוניים
- [ ] **אתה:** חשבון מפתח ב־Google Play (תשלום חד־פעמי). נדרש לפני הפצה, גם לבודקים.
- [ ] **אתה:** ייעוץ משפטי לפרטיות: חוק הגנת הפרטיות, תקנות אבטחת מידע, ודרישות Google Play למיקום. האפיון מציין שהוא לא תחליף לייעוץ משפטי.
- [ ] **אתה:** לבדוק את תנאי השימוש ב־GTFS של משרד התחבורה ובנתוני OpenStreetMap, ומה חובת הייחוס (קרדיט) לכל אחד מהם.
- [ ] **שניהם:** לבחור ספק מפות לאפליקציה, ולבדוק עלות לפי כמות שימוש.
- [ ] **שניהם:** שירות חיפוש כתובות ומקומות (geocoding). היום אפשר לחפש רק לפי שם של תחנה או של מקום שמור.
- [ ] **אתה (אופציונלי):** לפנות לסדנא לידע ציבורי (Open Bus) ולספר להם על השימוש ב־Stride.

## 4. עבודה טכנית לשלב 0 (היתכנות)
- [ ] **פיתוח:** להריץ את המנוע שנבחר על ה־GTFS של כל הארץ ועל OpenStreetMap, ולהשוות לתוצאות של אב־הטיפוס.
- [ ] **פיתוח:** ניתוב הליכה אמיתי לפי רחובות. היום ההליכה מחושבת בקו ישר כפול 1.3.
- [ ] **פיתוח:** שרת ראשון: חיפוש מסלול דרך המנוע, ומתווך זמן אמת (בהתחלה מול Stride, אחר כך מול SIRI-SM).
- [ ] **פיתוח:** אב־טיפוס Android מינימלי: מקליט Session (רק כשהאפליקציה פתוחה), מזהה הליכה ועצירה, ומציג ציר זמן.
- [ ] **שניהם:** נסיעות בדיקה אמיתיות עם הטלפון: איכות GPS ברכבת ובאוטובוס, וצריכת סוללה.
- [ ] **שניהם:** להגדיר איך מודדים דיוק (מה נחשב "זמן הגעה נכון"), ולאסוף נתוני בסיס לפני שמבטיחים שיפור.
- [ ] **פיתוח:** לבדוק את זמן האמת מול המציאות, למשל להשוות בתחנה מה האפליקציה הציגה ומתי הגיע האוטובוס בפועל.

## 5. מה חסר בפרויקט עצמו
- [ ] מאגר git וגיבוי (ראו סעיף 1).
- [ ] קוד Android: אין עדיין.
- [ ] שרת: אין עדיין.
- [ ] כיסוי: אוטובוסים רק בתוך תל אביב, ונתונים ליום אחד בכל פעם. אין אוטובוסים בערים אחרות.
- [ ] מחירי נסיעה: לא מחושבים, אף שהם בדרישות (FR-02).
- [ ] נגישות בתחנות ומעליות: אין נתונים.
- [ ] רמת ביטחון: אב־הטיפוס מציג "± דקות". האפיון מבקש תוויות גבוהה, בינונית או נמוכה, עם הסבר.
- [ ] התאמה אישית: מוצגת רק כנתון מדומה. אין עדיין מדידות אמיתיות.
- [ ] מסמכים חסרים מהאפיון (פרק 20): מפרט טכני, מסכי Wireframe, סכמת בסיס נתונים, חוזי API, תוכנית בדיקות, מדיניות פרטיות.
- [ ] בדיקות: יש בדיקות רק למנוע המסלולים ולזמן האמת. אין בדיקות לממשק, ואין בדיקה אוטומטית שרצה בכל שינוי.
- [ ] העדכון היומי האוטומטי רץ רק כשהמחשב הזה דולק. לשרת אמיתי הוא יעבור בהמשך.

## הסדר המומלץ
1. git (חצי שעה).
2. לשלוח את הבקשה למשרד התחבורה (היום).
3. השוואת מנועים ובחירה (משימה מוכנה).
4. ההחלטות מסעיף 2, לפחות אזור הפיילוט, חשבון משתמש ותקציב.
5. אב־טיפוס Android שמקליט נסיעה, ונסיעות בדיקה.
6. רק אחר כך: שרת מלא, MVP ופרטיות משפטית.
